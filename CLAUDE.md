# Conventions

## Naming: it is Decaid, not REA

The middleware is **Decaid**. "REA" is the old name and is no longer used — do
not introduce it in prose, comments, commit messages, docs or issue text.

Three things keep the old spelling because they are literal identifiers, not
names, and changing them breaks something:

| Keep | Why |
|---|---|
| `.reaplugin` (e.g. `streamline-settings.reaplugin`) | Decaid's plugin-folder format. Renaming it makes the plugin uninstallable. |
| `REA_PORT`, `reaHostname`, `getReaSettings`, `setReaSettings` | Identifiers in vendored skin code. Canon is the skin (see below) — rename them there, not here. |
| `settingsCategory: 'rea'` in `settings-tree.js` | A category id in vendored code. Its label already reads "Decaid Settings". |

## Vendored code

`settings-plugin/src/app/**` and `settings-plugin/src/vendor/**` are **copies**,
regenerated by `npm run sync` / `npm run watch:sync`. So is
`settings-plugin/src/styles/skin-vars.css`.

Never edit them directly — the next sync reverts you. Canonical settings code
lives in `decentespresso/streamline-js` under `src/settings/`; the port's own
edits to it live as declarative patches in `settings-plugin/sync-upstream.mjs`.
If a file is generated, change the generator.

Code owned here, and edited here: `src/plugin.ts`, `src/pages/`, `src/utils/`,
`src/assets/`, and in `src/app/`: `main.js`, `prefs.js`, `api-base.js`,
`return-to-skin.js`, `modules/ui-lite.js`, `modules/dye2-admin.js`,
`modules/profiles-lite.js`.

## Before committing

```
cd settings-plugin && npm run build && npm test
```

`streamline-settings.reaplugin/` is build output but **is** committed — keep it in
step with the source, or the release workflow warns that the committed build is
stale.
